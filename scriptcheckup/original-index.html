Reinit-баг и readback:
что происходит и как лечить

    


      

        case 01 · domain reload · dirty statics
        
Reinit-баг

        
В Project Settings → Editor → Enter Play Mode Options Unity может не перезагружать домен приложения. Тогда память процесса живёт между запусками: статические поля сохраняют значения прошлой сессии, синглтоны указывают на уничтоженные объекты, статические события держат подписки, счётчики ID продолжаются — и второй запуск ведёт себя иначе, чем первый.

        
    
          
  • Симптом: в первом запуске всё чисто, во втором события срабатывают дважды, спавн перезаписывает данные, появляются «двойные» синглтоны в DontDestroyOnLoad.
    • 
          
  • Симптом: NullReferenceException на старте сцены — Instance уже «не null», но объект уничтожен.
    • 
          
  • Проверка: выключите Domain Reload в Enter Play Mode Options и запустите сцену дважды. Разница в поведении = reinit-баг.
    • 
          
  • Быстрая разведка: в консоли отключите Collapse, оставьте фильтр Warnings и посмотрите, что печатается ДО первого Start().
    • 
        

        

        

          
          
        

      


      

        case 02 · gpu → cpu · pipeline stall
        
Readback

        
Любая синхронная вычитка данных с GPU заставляет пайплайн ждать: CPU стоит на месте, пока GPU не отдаст копию, а GPU ждёт, пока CPU не разберёт очередь команд. Отсюда спайки на 10–40 мс при «безобидном» чтении пикселей или буфера.

        
    
          
  • Виновники: Texture2D.ReadPixels, ComputeBuffer/GraphicsBuffer.GetData, ScreenCapture.CaptureScreenshot, Camera.Render() с чтением, AsyncGPUReadback.WaitAllRequests(), чтение targetTexture в тот же кадр.
    • 
          
  • Симптом: просадка ровно на кадре скриншота/замера цвета; в Profiler маркер Wait on GPU или GPU.WaitForPresent.
    • 
          
  • Правило: читать через кадр-два и всегда асинхронно. Замеры яркости/цвета — по уменьшенной копии 16×16, а не по полному экрану.
    • 
          
  • Плюс: AsyncGPUReadback отдаёт NativeArray без аллокаций в GC, а Apply(false, true) освобождает CPU-копию текстуры.
